# DB 및 JPA 재설계 1차 현황 분석 보고서

## 1. 작업 목표

기존 정책과 구현을 조사하고 실제 DB와의 차이·예매 정합성 위험·재사용/재설계 후보를 구분한다. 새 ERD를 확정하거나 애플리케이션/DB를 수정하지 않는다.

## 2. 완료한 작업

- 루트 AGENTS.md, 프로젝트 가이드, 인증 설계/SQL, 기존 보고와 시드 기록을 확인했다.
- 하위 에이전트 두 명에 엔티티/관계 조사와 API/서비스/테스트 의존성 조사를 읽기 전용으로 분배하고 Main이 근거와 문서를 통합했다.
- 7개 JPA 엔티티의 전체 필드/PK/관계/유일성, 상태·시각·삭제·감사·락 표현을 조사했다.
- 실제 DB 조회 시도는 Docker 접근 권한 거부로 실패했다. MySQL SQL은 실행하지 않았다. 실제 테이블/컬럼/제약/인덱스 및 데이터 불일치는 미확인으로 명시했다.
- 저장소 수동 DDL과 JPA의 CHECK·collation 차이, 재고 집계 의미, 회원·권한/검수·선점·예매·결제 부족 구조 및 영향 범위를 기록했다.

## 3. 변경 파일 및 DB 구조

- `docs/database/current-schema-analysis.md`: 매핑 전수 조사, 현행 동작과 의존성, DB 접근 실패와 미확인 항목, 후속 metadata 확인 절차.
- `docs/database/schema-gap-analysis.md`: 확인한 차이, 위험 우선순위, 유지/수정/신규/폐기 후보와 사용자 결정사항.
- `reports/2026-10-28-db-analysis.md`: 본 보고서.
- DB 구조/데이터, JPA·서비스·API·프런트·설정·기존 보고서는 수정하지 않았다. seed/서버/Docker 컨테이너 생성·시작·종료도 하지 않았다.

## 4. 주요 결정과 근거

- 실제 DB 접근 불가를 소스 추정으로 채우지 않았다. JPA 선언, 저장소 DDL, 과거 실행 기록, 이번 확인 결과를 구분했다.
- 과거 보고의 app_user 부재/존재 기록은 시점이 다른 이력이므로 현재 사실로 승격하지 않았다.
- 기존 공연/회차/물리 좌석/회차별 좌석/공연별 판매 정책 분리는 유지 후보로 두고 예매 수명주기와 권한·소유권·검수 중심의 재설계를 제안했다.
- 설계 선택지는 제안만 했으며 사용자의 정책·아키텍처 승인 전 새로운 ERD/마이그레이션을 확정하지 않았다.

## 6. 알려진 문제 및 리스크

- 실제 스키마 접근 불가로 분석 범위 2와 실제 DB 기준 불일치 판정은 미완료다. 테이블 부재·제약 누락·실제 중복 데이터 유무를 단정할 수 없다.
- 등록 unique는 중복 예매 보장이 아니며 선점/확정/실패/만료 모델과 동시성 검증이 없다.
- 공개 잔여 좌석 수는 현재 등록 좌석 수다. 승인·소유권·역할 및 거래 이력도 추가 설계가 필요하다.
- 기존 인덱스·실행계획·트래픽 측정 없이 성능 병목이나 신규 인덱스를 확정하지 않았다.

## 7. 미완료 사항과 다음 작업

- 접근 가능한 세션에서 대상 DB의 metadata를 읽기 전용 수집하고 JPA와 실제 DDL을 대조한다.
- 개인정보 없는 정합성 집계 후 선점/예매 수명주기 정책부터 사용자 결정을 받아 대안을 비교한다.
- 이번에는 문서만 생성하고 Commit·Push 및 Worktree 동기화는 수행하지 않는다.
- 학습 포인트: UNIQUE로 표현한 행 유일성과 트랜잭션 안의 상태·소유권·만료 조건을 함께 보장하는 예매 정합성을 구분해야 한다.
