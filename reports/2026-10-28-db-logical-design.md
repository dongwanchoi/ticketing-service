# 2단계 목표 논리 ERD 및 수명주기 초안 보고서

## 1. 목표

확정 요구사항과 기존 DB 실측을 근거로 Buyer/Seller/Admin과 예매 핵심 흐름을 수용하는 논리 모델 초안을 작성한다. 정책·ERD는 확정하지 않으며 코드·DB·기존 데이터를 변경하지 않는다.

## 2. 완료한 작업

- AGENTS.md, TICKETING_PROJECT_GUIDE.md, current-schema-analysis/schema-gap-analysis, DB metadata 검증 보고서와 관련 서비스/시드 소스를 확인했다.
- 하위 에이전트 두 명이 회원/콘텐츠·좌석/판매 영역과 선점/거래/동시성 영역을 읽기 전용으로 검토했다. Main이 통합 후 두 영역의 교차 검토를 받았다.
- 확정 요구(F), 현행 사실(C), 승인 전 제안(P)을 구분했다. 기존 7개 엔티티와 실측 관계·unique를 우선 재사용한다.
- 다좌석 그룹안 기준 신규 8개, 총 15개 논리 엔티티를 제시했다. 단일좌석·단일역할·판매자 자격 통합 등 더 작은 대안도 명시했다. 물리 테이블 수는 미확정이다.
- Mermaid ERD 2개와 상태 전이 9개, 엔티티별 속성/키/카디널리티/시각/이력/삭제 표, 기존 스키마 대비 변경 후보 및 미확정 결정 D1~D8을 작성했다.
- 실제 DB의 판매 정책 누락 1건은 구조상 가능한 생성 경로와 해당 행의 역사적 원인 미확인을 구분하고 비판매 유지/명시적 PREPARING 등록 등의 후보만 기록했다.

## 4. 설계 후보와 판단 근거

- 공연/회차/공연장/물리 좌석/회차 재고/공연별 판매 정책은 유지한다. category enum·posterUrl·castText·gradeLabel로 우선 표현하고 별도 마스터/이미지/출연진/등급 테이블의 필요성을 승인 전 과장하지 않았다.
- Role은 고정 코드이며 복수역할을 선택할 때만 UserRole이 정당화된다. SellerProfile 승인과 공연 검수는 별도 정책이다. Admin 부여·자기승인 방지·회수 후 진행 거래는 미확정이다.
- SeatHoldItem은 과거 선점 좌석·가격 보존과 묶음 원자성의 근거다. 테이블 수를 줄이기 위해 JSON 좌석 목록이나 FK 없는 거래 모델로 대체하지 않았다.
- 실패/만료 시도가 다음 구매를 막지 않게 Reservation/Item은 확정 때만 생성하는 안을 제안했다. 취소 좌석 재판매 금지안과 Item.sessionSeatId 영구 UNIQUE/CANCELLED_BLOCKED를 일치시켰다.
- 로컬 동기 모의 결제 성공·확정·발급을 한 트랜잭션으로 처리하는 제안이다. 실제 PG·비동기 UNKNOWN/보상은 미래 범위이며 같은 보장을 자동 적용하지 않는다.
- 공통 DomainEvent는 대상별 FK와 선택 typed 속성으로 검토하되 sparse 컬럼·FK 비용을 명시했다. 전체 콘텐츠 revision 복원은 보장하지 않으며 전용 이력 대안은 D7이다.

## 6. 알려진 문제 및 리스크

- 초안의 15개 엔티티는 D1/D2/D7 가정에 따라 줄거나 달라질 수 있다. 새로운 ERD는 미확정이다.
- 선점 TTL·가격 고정·실패 후 재시도·만료/판매 종료 경계·취소/재판매 정책 미승인 상태에서 물리 UNIQUE와 거래 코드를 구현하면 위험하다.
- 재고만 잠그고 정책/권한 변경을 직렬화하지 않으면 검수 철회·권한 회수와 구매가 경합한다. 락 순서·재시도·100명 DB 검증은 미실행이다.
- 기존 공연의 판매자/검수 backfill과 누락 Sale 1건은 사용자 확인 없이 자동 보정하지 않는다. 실제 원인 증거는 부족하다.
- 공통 감사는 전체 변경 내용 복원·개인정보 보존정책을 해결하지 않는다. 상세 범위와 보존·접근권한은 별도 승인해야 한다.

## 7. 미완료와 다음 결정

우선 D2/D3/D4: 단일좌석 또는 동일회차 묶음, TTL/가격고정, 결제 실패·만료 판단·확정 경계, 전체취소/재판매 여부를 승인한다. 그다음 역할/자격·검수/콘텐츠·보존·시각과 경쟁 방식의 대안을 좁힌다. 승인 후에만 물리 ERD·DDL/JPA 변경·비파괴 이행·rollback 및 실제 DB 경쟁 시험 계획을 작성한다.

핵심 원리: 과거의 선점/거래 이력과 현재 재고의 유일한 점유 권위를 분리하고, 결제·확정·발급을 같은 정합성 경계에 묶어야 한다.
